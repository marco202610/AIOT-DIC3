# Blockchain 感測資料系統：開發進度與技術說明

**整理日期：** 2026-11-25  
**版本範圍：** 本機原型（包含尚未提交的修改）

## 1. 系統用途

透過手機瀏覽器收集三軸加速度資料，停止錄製後打包、加密及上傳。採用鏈下保存密文、鏈上錨定 SHA-256 摘要的設計，提供資料完整性比對機制。雜湊不能證明感測資料本身真實，也不能還原原始資料。

## 2. 系統架構

```text
手機瀏覽器
  ├─ 錢包登入與感測授權
  ├─ DeviceMotionEvent 三軸加速度
  ├─ IndexedDB 本機持久化
  └─ AES-256-GCM 加密與 SHA-256 摘要
          │ HTTPS / JSON
          ▼
Cloudflare Worker 相容 API
  ├─ 錢包簽章驗證與工作階段
  ├─ 密文上傳、查詢與配額
  ├─ IOTA EVM 摘要錨定介面
  └─ 公開摘要 API ──▶ AI 助理整合介面
          │
          ▼
D1 資料模型與 migrations
```

此圖描述原型模組，不代表已完成雲端部署或真實鏈上交易。

## 3. 已實作功能

### 3.1 錢包驗證

- 使用 EIP-1193 provider 與 personal_sign，後端透過 EIP-191 驗證一次性登入簽章。
- Challenge 綁定來源、錢包與瀏覽器識別，具有效期限及單次使用限制。
- 登出、工作階段到期或切換錢包時停止感測，隔離不同錢包的本機紀錄。

### 3.2 手機感測與本機持久化

- 使用 DeviceMotionEvent 的 acceleration 收集 x、y、z 三軸加速度。
- 最高取樣頻率 4 Hz，單次最多 2,880 筆；最高頻率下約 12 分鐘。
- 樣本逐筆寫入 IndexedDB，停止後等待寫入完成再加密；頁面進入背景或儲存寫入落後時停止取樣。

### 3.3 加密、摘要與備份

- 每個資料包採用隨機 256-bit 金鑰與 96-bit IV，以 AES-256-GCM 加密。
- JSON 資料包包含版本、演算法、IV 與密文；SHA-256 計算對象為完整 JSON 字串的 UTF-8 位元組。
- 密文與復原金鑰分開備份，離線復原時先比對摘要，再驗證及解密。
- 伺服器密文查詢具有身分隔離機制。
- IndexedDB 保存的明文樣本與復原金鑰仍屬敏感資料，裝置或同源程式遭入侵時可能被讀取。

### 3.4 密文上傳與資料庫

- 後端驗證工作階段、資料包格式及摘要。
- 相同資料包重送採冪等處理；相同 ID 對應不同內容時拒絕。
- 透過資料庫寫入機制限制資料包配額及新增速率。
- 使用 Web Locks 與紀錄鎖序列化加密及上傳操作。

### 3.5 公開資料與鏈錨定

- 公開感測批次採明確同意機制，撤回同意後不再出現在公開查詢及摘要。
- 加密錄製資料與公開批次分離，不納入 v1 公開摘要。
- 鏈錨定需獨立同意，狀態包含 not_requested、pending、failed、confirmed。
- 目前實際鏈寫入停用，測試使用傳輸替身；測試確認不等同真實交易收據。

### 3.6 AI 助理整合

- 透過獨立 HTTP JSON 公開摘要 API 整合 AI 助理。
- 摘要包含 schema 版本、產生時間、公開事件數及可選的最新錨定資料，不包含錢包、裝置或個人批次識別碼。
- 驗證摘要格式與時間新鮮度；資料無效、過期或不可用時，不捏造事件數或上鏈結果。
- 語音後端具可信摘要來源注入介面與固定格式繁體中文回覆邏輯，尚不能視為真實語音端到端驗證。

## 4. API 功能摘要

| 方法 | 用途 |
| --- | --- |
| POST | 錢包登入 challenge、簽章驗證與登出 |
| POST | 公開批次同意狀態更新 |
| POST | 加密資料包上傳、查詢與摘要錨定請求 |
| GET | 公開彙總摘要與公開感測批次 |

## 5. 技術組件

| 技術 | 用途 |
| --- | --- |
| JavaScript / Web Crypto API | 感測、加解密、摘要及錢包連接 |
| IndexedDB / Web Locks | 本機持久化與操作序列化 |
| Cloudflare Worker / D1 相容介面 | 工作階段、資料包儲存與公開摘要 |
| IOTA EVM 相容介面 | 摘要錨定抽象與狀態管理 |
| Node.js 26 / SQLite | 本機測試與 migration 測試 |

## 7. 與 AIOT-DIC3 研究方向的關聯

此原型可作為戶外運動情境感知 AI 教練的候選感測資料安全與完整性驗證模組。手機感測可提供運動相關輸入，公開摘要介面可供 AI 助理整合。此關聯為研究整合方向，尚未證明已完成與 AIOT-DIC3 的端到端整合，也不代表加速度資料足以判斷生理風險或提高運動安全性。
